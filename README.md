# تطبيق مراقب مستوى الخزان (Flutter)

تطبيق موبايل (Android/iOS بكود واحد) يتواصل مباشرة مع جهاز ESP32 على الشبكة
المحلية، حسب مستند المواصفات + كل بنود مستند طلب التعديلات.

## بنية المشروع

```
lib/
  main.dart                    الثيم والألوان + نقطة الدخول
  services/device_service.dart الاكتشاف التلقائي + نداءات الـAPI
  widgets/animated_tank.dart   رسم الخزان + تموّج الماء المتحرك
  screens/root_screen.dart     شاشة الاكتشاف + شريط التنقل السفلي
  screens/home_screen.dart     تبويب الرئيسية
  screens/calibration_screen.dart تبويب المعايرة
  screens/settings_screen.dart تبويب الإعدادات
```

هذا مجلد `lib/` فقط + `pubspec.yaml`. لتشغيله كمشروع كامل:

```bash
flutter create --org com.example --project-name watertank_app .
# بعدين استبدل مجلد lib/ وملف pubspec.yaml بالي هون
flutter pub get
flutter run
```

## 📲 أسهل طريقة تحصل فيها على ملف APK جاهز (بدون تثبيت أي شي عندك)

المشروع فيه ملف `.github/workflows/build_apk.yml` بيخلي GitHub يبني الـ APK
تلقائياً بالسحابة، مجاناً. الخطوات:

1. اعمل حساب مجاني على github.com (إذا ما عندك)
2. اعمل Repository جديد (خاص Private أو عام، إلك الخيار)، وارفع له **كل
   محتويات هذا الـzip** (اسحب وأفلت الملفات مباشرة بصفحة الريبو، أو استخدم
   git)
3. روح لتبويب **Actions** بأعلى صفحة الريبو — رح تلاقي "Build Android APK"
   شغّال لحاله (أو دوس "Run workflow" يدوياً إذا ما اشتغل تلقائياً)
4. استنى ٣-٥ دقائق لحد ما تخلص، بعدين افتح الـ run وبتلاقي بالأسفل تحت
   "Artifacts" ملف اسمه `watertank-app-apk` — حمّله
5. فك الضغط عن الملف المحمّل، بتطلع لك `app-release.apk` — انقله عالموبايل
   (عبر كابل، أو رفعه لـ Google Drive وتحميله من الموبايل) وثبّته (لازم تفعّل
   "السماح بالتثبيت من مصادر غير معروفة" بإعدادات أندرويد أول مرة)

بهيك بتصير عندك تطبيق APK حقيقي منصّب على موبايلك، بدون ما تحتاج تثبت Flutter
ولا Android Studio عندك إطلاقاً.

> ملاحظة: هاي الطريقة لنسخة أندرويد فقط. نسخة iOS بتحتاج حساب Apple Developer
> (مدفوع) للتوقيع، فهاي أصعب تُعمل بدون جهاز Mac — إذا عندك آيفون وبدك نفس
> الطريقة إلو، قلي وأشرحلك الخيارات المتوفرة.

## ⚠️ ملاحظة تقنية مهمة: السماح باتصال HTTP على الشبكة المحلية

جهاز الـESP32 يعمل كـ HTTP عادي (بدون HTTPS، حسب التصميم بمستند المواصفات).
كلا النظامين Android وiOS يمنعان اتصالات HTTP الصريحة افتراضياً، فلازم فتح
استثناء لهيك — **بدون هالخطوة رح يفشل كل اتصال بالجهاز**:

### Android
في `android/app/src/main/AndroidManifest.xml` داخل وسم `<application>`:
```xml
<application
    android:usesCleartextTraffic="true"
    ...>
```

### iOS
في `ios/Runner/Info.plist` أضف:
```xml
<key>NSAppTransportSecurity</key>
<dict>
    <key>NSAllowsLocalNetworking</key>
    <true/>
</dict>
<key>NSLocalNetworkUsageDescription</key>
<string>التطبيق يحتاج الوصول للشبكة المحلية للتواصل مع جهاز مراقبة الخزان</string>
```
(بدءاً من iOS 14 راح يظهر تصريح "Local Network" للمستخدم أول مرة — هذا طبيعي ومطلوب.)

> هاي بالمناسبة هي على الأغلب سبب مشكلة "القراءة الحية غير شغّالة" (بند 6) إذا
> كانت النسخة التجريبية على Replit مستضافة كصفحة HTTPS: أي صفحة HTTPS
> المتصفح بيمنعها تلقائياً من طلب HTTP عادي (Mixed Content) — نفس المشكلة
> بتنطبق لو حاولنا نستضيف هذا التطبيق كصفحة ويب بدل تطبيق موبايل حقيقي، ولهيك
> تم بناؤه هون كتطبيق Flutter فعلي بدل صفحة ويب.

## ملخص التعديلات المطبّقة (حسب مستند طلب التعديلات)

| # | الطلب | كيف تم التنفيذ |
|---|-------|-----------------|
| 1 | إصلاح Layout زر "اقرأ الآن" | `calibration_screen.dart` — `Row` مع `Expanded` للحقل + `SizedBox(width:92)` ثابت للزر، ما بينكسر برا البطاقة على أي حجم شاشة |
| 2 | حذف "المسافة الحالية" من الرئيسية | غير موجودة إطلاقاً بـ`home_screen.dart` |
| 3 | حذف "قوة الإشارة" من الإعدادات | `DeviceInfo` ما عادت تحتوي rssi، والبطاقة بـ`settings_screen.dart` ما بتعرضه |
| 4 | حذف "عنوان IP" من الإعدادات | نفس الشي — غير معروض، وأصلاً التطبيق ما بيحتاجه بفضل الاكتشاف التلقائي |
| 5 | تصحيح النص لـ"قراءة مباشرة من حساس خزان المياه" | `home_screen.dart` تحت العنوان الرئيسي |
| 6 | القراءة الحية غير شغّالة | `Timer.periodic` كل 2 ثانية بالرئيسية والمعايرة يستدعي `GET /api/status` فعلياً (مو مرة وحدة بس) — وتأكد أيضاً من ملاحظة الـHTTP/HTTPS أعلاه |
| 7 | الاكتشاف التلقائي (بدون خانة عنوان يدوي) | `device_service.dart`: مسح متوازٍ لـ192.168.1.x ثم 192.168.0.x مع Timeout قصير، يحفظ آخر IP ناجح بالـcache (`shared_preferences`) لتسريع الفتحات القادمة. خيار الإدخال اليدوي موجود بس مخفي (ضغط مطول على 💧 بشاشة "تعذر الاتصال") |
| 8 | تحريك الماء (Wave Animation) | `widgets/animated_tank.dart`: `CustomPainter` + `AnimationController` مستمر يرسم موجة جيبية متحركة أفقياً فوق سطح الماء |

## بخصوص ملف `watertank.ino`

كود الجهاز (الـESP32) المرفق أصلاً متوافق تماماً مع كل نقاط الوصول اللي
التطبيق بيعتمد عليها (`/api/status`, `/api/info`, `/api/calibrate`,
`/api/wifi`) — ما احتاج أي تعديل على الفيرموير، كل التعديلات كانت على مستوى
التطبيق فقط.

## سؤال التصميم المفتوح من مستند المواصفات (القسم 4)

بما إنه التطبيق صار يعتمد اكتشاف تلقائي بالكامل، سيناريو "أول استخدام" (شبكة
WaterTank-Setup) بيبقى **خارج التطبيق** حالياً: المستخدم يتصل بالشبكة يدوياً
من إعدادات الموبايل زي أي شبكة واي فاي عادية، ثم يفتح المتصفح على
`192.168.4.1` (هاي الصفحة موجودة جاهزة بالفيرموير `setupPage()`). ممكن
لاحقاً نضيف شاشة "إضافة جهاز جديد" جوا التطبيق نفسه توجّه المستخدم خطوة
بخطوة إذا حبيتوا — خليها إذا بدكم أعمل هالإضافة.
